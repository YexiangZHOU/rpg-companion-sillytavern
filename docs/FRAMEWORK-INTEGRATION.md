# 通用框架：聊天接入

本版本在本地实现真实SillyTavern边界，部署与真实模型验收须独立进行。第一阶段原型的历史结果见FRAMEWORK-PROTOTYPE.md。

## 使用

新聊天（空聊天或仅开场、没有旧跟踪记录）自动采用通用框架；已记录旧tracker或已有多轮的聊天保持兼容模式。右侧“本聊天数据框架”可切换。切换不会把旧百分比/默认六属性转换成已确认数据，也不删除旧记录；切回兼容模式恢复旧渲染与跟踪。通用结构首次依据当前角色卡、世界书、玩家描述与剧情建立，没有规则选择向导。

通用模式随主聊天回复更新，与旧generationMode的Together/Separate/External配置独立；Separate/External旧自动刷新在此模式停止，避免两个模型更新器同时写数据。通用数据当前使用rpg-framework文本事务，模型不用调用新的原生工具；骰子仍使用现有原生工具或文本协议。只接受正常生成；quiet、冒充、继续未完成回复、被抑制的引导与dry-run不更新游戏。

模型可创建任意类别/字段。对象kind的player/npc/scene/encounter是可选的界面位置提示，不是游戏设定分类；场景与NPC在左切换查看，玩家及其他对象在右，遭遇对象在原遭遇窗口。动态组别与字段、摘要、资源条、集合、未知、手动编辑、命名、锁和归档使用同一数据内核。details布局默认折叠详细内容。

## 持久化

当前回复与每个swipe的extra存储完整定义/值/锁快照，并镜像至swipe_info。只有快照与当前文字精确匹配时才能恢复；修改/删除/切换回复退到仍有效的祖先。所有游戏数据属于聊天，账号设置只保存原有功能偏好。编辑锁/数值时保存当前回复；同一个保存过程拒绝并发编辑。生成期间手动修改数据时，旧基准的模型回复不覆盖手动结果。

ST 1.19的上下文saveChat会捕获错误；调用结束不能证明保存成功。接入层使用正式saveChat后通过当前账号聊天读取接口比较模式、框架与头像快照，再隐藏接受的框架块并显示“已保存”。失败回退本地变动并保留结构块，提示用户检查连接。网络回读失败也可能意味着服务器已保存但未确认；刷新以服务器有效记录为准，不自动强制覆盖或承诺服务器完全未变。

## 骰子、遭遇和绘图

- 骰子复用程序随机源、玩家点击/外部结果/自动模式及主聊天回传。通用提示不默认d20，支持NdM与整数修正（优势/劣势仍仅1d20）；不新增通用公式解释器。骰池规则需模型依据真实原始骰点按声明的规则解释。
- 遭遇复用原窗口、关闭/结束交互及主聊天草稿目标选择，不另起战斗模型循环。内容为kind=encounter对象的动态数据，不强制HP/AC/法术位、固定先攻/回合或攻击类型；结束归档对应对象。manual/proposal/auto使用既有聊天/账号偏好。尚非任意游戏规则引擎，模型结算必须有当前游戏依据。
- 场景图仍通过原生/sd与既有队列生成，读场景/公开对象描述/外观与正文动态，自动/提议/手动沿用原偏好。内心想法与任意数值不送入画面描述。
- 右侧可为当前对象生成头像，外观字段使用“外观/相貌/外貌/appearance”文字或模型记录的公开外观。auto允许rpg-portrait请求，外观未变且已有同内容图片时不重复付费生成；手动可以刷新。头像锁、关闭、坏URL及切聊天/回复/外观变化后的迟到结果受到保护。图片路径仅原生/user/images，不让模型写任意URL。
- 头像是本聊天分支的对象图像，不自动覆盖账号persona头像或角色卡原图。失败请求保留可见；成功请求仅在显示层隐藏，保持骰子/场景的原始回复身份。

## 验证与边界

运行npm run test:framework。纯内核/聊天生命周期/保存回读验证使用合成数据，浏览器验证使用实际框架/sceneImage/原遭遇适配器和本地ST接口桩。接口桩与真实模型输出、服务器权限、第三方卡片服从性及不同ST版本不是同一验证对象，上线后必须另行验收。

当前没有自动旧数据合并迁移、计算字段、任意脚本、嵌套集合或全套规则执行器。旧聊天保留独立兼容视图而非无声重建。空场景和未知值不填默认天气/资源。许可沿用原LICENSE/README的AGPL-3.0-or-later与原作者署名，修正原package.json的MIT元数据矛盾。
