# 我的角色面板重设计（旧设计，已被通用框架草案取代）

2026-10-04 用户修订：组别及组内字段由模型初始化，玩家无需选择规则模板。最新方向见 [通用 RPG 框架](UNIVERSAL-RPG-FRAMEWORK.md)。下文保留旧设计背景，固定分页/生命/等级不再是通用界面的默认结构；旧 SVG 仅供布局和密度参考。

此文档是设计方向，不表示界面已经实现。现有功能基线独立保存于 `deployed-baseline-2026-10-04`；开发分支为 `feat/player-panel-redesign`。

## 问题与目标

当前玩家界面叠加通用状态、人物属性、头像工具和战斗资源，身份与状态入口重复。百分比生命与绝对生命并列，含义容易混淆；默认数值也容易被误认为已确认的人物表。垂直列表占用大量空间，用户切换物品与任务需要长距离滚动。

目标是把“我的角色”作为统一角色视图，优先展示当前身份和下一步行动需要的信息；规则专属字段按启用的人物表模式显示，适用于西幻、科幻和其他背景。

## 信息结构

1. 固定角色概览：清晰头像、当前冒险角色名、已确认的等级/身份、异常状态。头像放大、替换、生成与锁统一置于头像菜单。没有确认冒险身份时显示人设回退和待确认提示。
2. 核心资源：当前/上限生命、精力及已确认的规则资源。显示紧凑对齐的条与数值；无数据时显示未记录，不补满血。绝对 HP 已确认时作为主生命，旧百分比生命作为可选通用状态项，不自动换算。
3. 紧凑分页：`概览`、`人物表`、`物品`、`任务`。概览包含少量关键状态与最近有效变化；人物表按规则模式展示属性、能力与法术位；物品复用原分类、数量、编辑与锁；任务复用原主线、支线和编辑行为。
4. 详情与编辑：外观/描述等长文本按需展开；每个区域统一编辑和锁入口。自定义字段保留名称、排序、可见性，不把所有模式硬编码成六项属性。
5. 状态反馈：有效更新后短暂强调变化；锁定值不作更新动画。解析失败或数据尚未确认给出可理解的提示，不把“模型已声称更新”视为成功。

## 数据边界

- 首期新增 `playerViewModel` 读取现有聊天/分支快照，向一个玩家渲染器提供投影视图；不先把三个存储体系强行合并。
- 确认玩家身份来自 action state；头像来自当前聊天、当前身份的 portrait metadata；数值人物表来自 numeric state；通用自定义状态来自原 tracker 数据；库存与任务沿用原结构。
- 每个显示字段保留来源、确认状态、锁以及对应编辑动作。相同含义只展示一项主值；不同单位不混算。
- 所有写入通过既有持久化和分支逻辑；界面不得直接只改 DOM 或随意回写全账号设置。
- 规则模式、自定义字段、账号隔离、切换聊天、swipe、删除与刷新必须保持既有语义。数据迁移若必要，另行实现版本号和可回退方案。

## 交互与布局

- 保留左侧场景/右侧玩家、原箭头抽屉、自适应宽度和固定对话中心。
- 用户可设置显示字段与紧凑程度；窄侧栏属性使用 2–3 列，宽侧栏使用更多列；分页区独立滚动，角色摘要不会因长库存消失。
- 所有控件有中文/英文标签、明确锁定提示和键盘焦点；不靠 hover 才能操作。过长名称允许完整查看。
- 选择页面、折叠状态和滚动位置在同次重渲染保持，不改变其他聊天数据。

## 开发与验收顺序

1. 以合成数据做可交互原型：D&D、通用/科幻、自定义、尚未建卡和受伤/资源不足。
2. 确认信息结构后，实现纯数据投影和统一渲染器，接入现有编辑/锁/头像/检定。
3. 验收数值零值/未知/默认与确认差异、锁、模型更新、手动修改、重渲染、切换与历史分支隔离；复测原遭遇、骰子和场景图读取相同资源。
4. 桌面与手机测试阅读密度、键盘与焦点、无横向溢出以及抽屉开关后聊天中心不移动。
5. 完成可审阅差异、版本和恢复说明后再单独安排部署。现有生产实例不随 Git 提交自动更新。
