# 模型初始化的通用 RPG 框架（设计草案）

2026-10-04 用户要求：玩家无需预设规则，扩展不固定游戏设定；模型根据当前游戏初始化组别、组内字段与初值。此文档取代 PLAYER-PANEL-REDESIGN.md 中固定分页和资源的旧设计。已完成本地数据内核、通用面板、聊天事件/分支保存回读、旧模式隔离、通用遭遇窗口和绘图读取；生产部署与真实模型验收独立安排。实施边界见 [聊天接入说明](FRAMEWORK-INTEGRATION.md)，原型历史见 [原型说明](FRAMEWORK-PROTOTYPE.md)。

## 目标

模型结合角色卡、世界书、玩家描述和当前剧情定义需要记录的信息；扩展提供数据协议、校验、保存、通用控件、编辑/锁及历史恢复。属性、状态、物品、能力和任务都是可由模型创建的实例，不是必须存在的系统分类。

上一轮 SVG 的左右布局、紧凑风格和固定摘要可参考；固定人物表/物品/任务分页、生命/精力及 D&D 数值仅为特定游戏实例，不作为通用面板默认结构。

## 定义与数据

1. 定义：每个组别有稳定 ID、显示名、用途、所属对象、显示顺序与展示方式；字段有稳定 ID、名称、类型、说明、单位及可选范围。集合可以定义条目结构和子分类。名称与布局可变化，ID 不随改名变化。
2. 数据：保存字段当前值和集合条目，引用已存在的定义。未知明确表示，不用 0/100/10 代替；零是有效值。
3. 展示：摘要引用模型标记为重要的少量字段，下面的组别导航由定义生成。多组时使用换行/折叠导航，避免一条标签栏挤满所有组。
4. 关联：玩家、NPC 或其他跟踪对象分别持有数据，共享适用定义。场景可有动态组别；不能把 NPC 更新写入玩家。
5. 版本：定义、值、锁和关联同属当前聊天/回复分支的版本化状态，恢复历史时恢复当时的定义与值。

## 框架基础能力

- 数字、文字、布尔、选项、范围资源（当前/上限）、标签、记录与列表。
- 数值格、资源条、文本、标签、紧凑列表、可展开条目、进度等通用控件。
- 合法范围、单位、字段关联及显示偏好；资源条只在有范围时绘制，不自动补满。
- 模型声明内容与显示意向；扩展选择受控组件，不执行模型生成的 HTML、CSS、JavaScript 或任意表达式。
- 后续计算字段使用受限表达式与显式依赖，检查循环和未知输入，不用 eval。首期不承诺精算所有游戏规则。

## 模型初始化和更新

- 新游戏从现有设定生成最小必要定义与已知初值，玩家可直接描述行动，无需选择模板或完成强制配置向导。
- 缺乏依据的设定在正常叙事中澄清，缺乏依据的数值保持未知，不替玩家声称完成了人物创建。
- 初始化一次；后续按稳定 ID 更新数值/条目。出现新机制时再添加或调整定义，不每轮重建分类。
- 玩家能查看、修改、隐藏或锁定结构与值；结构自动初始化，不增加强制审核向导。
- 改名保留数据，移组保持引用，删除采用归档语义，不把本轮没提到的字段当作删除。归档保留历史。
- 更新为有编号、有基准版本的事务；校验定义/值/引用/锁后一次保存。重复提交不重复扣资源/加物品，过期版本不覆盖最新值，失败明确反馈。
- 面板反馈和下一轮上下文依据已接受且持久化的状态；模型文字声明不等于成功。JSON 大小、深度、条目数有技术上限。

## 界面

- 保留左场景、右角色与更多、原箭头抽屉、自适应宽度、固定聊天中心。
- 摘要展示当前对象名称/头像和模型选择的重点字段；不要求每个游戏具有生命、等级或职业。
- 组别名称、数量和字段由模型初始化，同一套控件生成紧凑页面；长文折叠，列表分类动态生成。
- 飞船护盾、门派声望、店铺资金都是数据实例，不成为源代码必选项。
- 中文/英文系统操作标签完整，动态内容尊重当前聊天语言；玩家锁定的名字/显示设置不被模型改回。重绘保持组别页、滚动和焦点。

## 骰子、遭遇战与绘图

- 模型按游戏声明检定主体、公式/修正和判定说明，引用相关字段 ID；保留玩家点击/模型发起模式，随机结果由程序生成。
- 不强制 d20、六属性修正、AC 或先攻规则。现有骰子/遭遇协议与 UI 的假设须移入兼容层或泛化，不能只改人物表渲染。
- 复用原遭遇窗口的目标选择、行动草稿与记录交互，资源/行动/回合及排序依据游戏定义，未声明的规则不补入。
- 头像/场景图通过对象身份、公开描述和当前动作读取数据；绘图不要求固定游戏组存在。

## 旧数据兼容

- 现有 tracker/numeric/action 快照通过版本明确的映射提供通用视图，读取旧聊天时不静默破坏原记录。
- 百分比健康与绝对 HP 保持不同字段/单位，不自动合并。旧默认值保留来源，不因新结构而成为已确认事实。
- 历史状态/物品/任务保留原名进入兼容视图，不成为新游戏必选模板。
- 切换聊天、swipe、删除、编辑、锁与刷新同时验定义和值；不依赖全账号设置存储游戏结构。

## 实现顺序

1. 通用协议、受控控件与兼容边界；用分类完全不同的西幻/飞船/经营/无数值叙事做动态原型。
2. 纯定义/状态校验和事务归约；验未知/零/负数/小数、自定义范围、重复/过期提交、锁、改名/归档和主体隔离。
3. 通用渲染器、模型初始化/更新上下文，接手动编辑及聊天/分支持久化。
4. 泛化骰子/遭遇/头像/场景读取；验旧游戏、无生命/等级的游戏、移动布局和聊天居中。
5. 差异/版本/回退审阅后另行安排部署。Git 提交不自动更新生产。
